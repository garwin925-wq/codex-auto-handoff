# Codex 自动上下文交接与 /compact 怎么选

[English](codex-handoff-vs-compact.md) · [配置指南](why-codex-auto-handoff.zh-CN.md)

| 方式 | 如何保留进度 | 谁开聊天并发送任务 |
| --- | --- | --- |
| `/compact` | 在当前聊天中生成摘要 | 继续使用当前聊天 |
| 手写 `HANDOFF.md` | 自选记录和原文引用 | 用户选项目、开聊天并提供文件 |
| 仅生成交接文件的工具 | 工具生成的检查点 | 由用户或另一个派发程序负责创建和发送 |
| Codex Auto Handoff | 结构化检查点、项目文件和仍生效的要求清单 | Codex 在同一已保存项目创建独立聊天，编号并发送已授权的下一步 |

还在排查一个故障时，`/compact` 可以保留当前聊天入口。阶段结束时，检查点能让下一步和验证标准更容易核对。想自行审阅交接、选择切换时机时，也适合手动交接。

**Windows 派发方式。** 优先用原生聊天工具。安装兼容 CLI 时，App Server 后备程序会核对工作区和设置，申请新聊天 ID 并启动接收回合。标题沿用“构建”“构建2”“构建3”。后备程序为每个来源聊天独占一份收据，用来防止重复创建。收据记录目标和回合状态，任务是否完成还要核对交接中指定的输出或测试。[Windows 验收记录](windows-acceptance.md)
