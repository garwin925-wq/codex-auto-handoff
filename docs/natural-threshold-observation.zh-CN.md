# Windows 实际上下文用量观测

[English](natural-threshold-observation.md)

2026-11-18 复用一条用于部署换聊、打包技能、发布 GitHub 和检查可发现性的项目长聊。本轮核对了已安装的 hook、发布脚本和验收证据，沿用原模型、上下文窗口和交接阈值。

- 环境为 Windows 11 25H2、Codex Desktop 26.1111.2228.0、CLI 0.169.0-alpha.11.1。
- PostToolUse 提醒和 PreCompact hook 均已启用且受信任。这只确认配置状态。
- 最新请求为 259,059 / 475,000 tokens，约 54.5%。截至测量时有 198 条可用样本，均未达到 70% 或 80%。比例使用最近一次请求的用量和该次记录的窗口大小。
- 本轮没有触发换聊。[受控接续验收](windows-acceptance.md)已单独验证新聊天在同项目执行下一步并写出预期结果。

## 2026-11-18 后续验证

### 恢复旧聊后在阈值以下完成任务

一条尚有本地验收任务的旧聊，上次记录为 203,171 / 258,400 tokens（78.6%）。原桌面客户端收到正常的任务接续要求后，报告的窗口变成 475,000 tokens。请求占用从 218,927（46.1%）增至 227,345（47.9%）。原聊使用合成数据完成了两项本地文件系统验收。没有调整阈值或填充上下文，本轮未触发换聊。

### 另一条真实任务自然触发换聊并完成下一步

在一条用于核查项目现有服务的日常聊天里，源日志记录到 PostToolUse 交接提醒，相邻样本为 430,090 / 475,000 tokens（90.5%）。原聊保存了交接文件，通过本机 Windows App Server 助手创建新聊。这次用户请求是正常的项目核查，助手按宿主正常审批流程派发。

通过 Codex App Server 核对，两个聊天 ID 不同，工作目录相同。原聊没有存储项目 ID，助手按目录匹配已保存项目，接收聊天的项目 ID 与收据一致。接收回合读取交接，完成只读服务和 DNS 检查并报告结果。回合和派发收据均为完成，且写入权已释放。第一条观察到的提醒已超过 90%，这次证据无法确认是否会刚过 80% 时触发、所有聊天的成功率，以及从头安装公开技能是否有相同行为。
